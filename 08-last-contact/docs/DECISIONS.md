# DECISIONS — 연락 기록

- **카톡 연동 방식**: 카카오 공식 API(로그인·친구 목록·메시지 보내기)에는 대화 기록·마지막 대화 시각 조회가 없다. 그래서 ① 대화 내보내기 파일 ② 알림 접근(NotificationListenerService) 두 가지를 쓴다. 알림 방식은 받은 메시지만 잡히는 한계를 화면에 명시.
- **본인 폰 직접 설치 전제**: Play 정책상 제한되는 READ_CALL_LOG·READ_SMS를 선택 기능으로 넣었다. 스토어에 올리려면 이 기능을 빼야 한다.
- **저장 단위**: 사람·날짜·경로 1건(`personId|day|channel` 유일 키). 같은 날 여러 번은 방향(받음/보냄/주고받음)과 최신 시각만 합침 → 내보내기 파일을 여러 번 가져와도 중복 없음.
- **날짜**: 기기 시간대 기준 LocalDate 문자열 + 선택적 UTC 시각. 경과 일수는 매번 오늘 기준 재계산.
- **내보내기 규칙**: 1:1(나를 뺀 1명)은 모든 대화일이 연락, 단체는 그 사람이 말한 날만. '나'는 설정의 내 카톡 이름 또는 방 제목과 다른 쪽으로 추정하고, 사용자가 확인·수정 후 저장. '나'로 고른 이름은 기억.
- **해석기 안전**: 글자 단위 읽기, 줄 2만 자·텍스트 100MB·ZIP 파일 200MB·항목 200개 한도, 원문 저장 안 함, UTF-8 실패 시 MS949 재시도.
- **이름 매칭**: 공백·대소문자 무시 완전 일치(부분 일치는 오연결 위험). 안 맞는 이름은 미확인 목록에 날짜만 쌓고 사용자가 연결.
- **번호 매칭**: 숫자만, +82/0082/82 → 0. 등록하지 않은 번호는 저장하지 않음.
- **통화**: 1초 이상만 연락으로(부재중·연결 안 된 발신 제외).
- **매일 작업**: WorkManager 1일 주기(정확한 시각 보장 안 함, 화면에 '대략' 안내). 알림·통화문자 자동 중 하나라도 켜져 있으면 유지, 앱을 열 때 기존 예약 시각은 유지(KEEP).
- **연락처**: 시스템 선택기(ACTION_PICK Phone)로 고른 한 명만 → READ_CONTACTS 불필요.
- **기술 버전**: 폴드 대시보드(07)와 같은 검증된 조합(AGP 8.11.1, Kotlin 2.2.0, Compose BOM 2025.06.01, Room 2.7.2) + WorkManager 2.10.1. 개발용 서명 키도 07과 같은 파일.
- **테스트 한계**: Robolectric 360×780dp + 입력칸 대화상자 idle 문제 → 해당 흐름은 실기기 테스트(androidTest)로.
