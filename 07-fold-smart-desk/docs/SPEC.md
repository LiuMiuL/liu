# 07. 폴드 스마트 대시보드 — 독립 앱 제작 명세서

> 앱 가칭: **Fold Smart Desk**

## 0. Claude에게 전달할 작업 명령

```text

이 문서를 끝까지 읽고 실제 Android 앱 개발을 시작해줘.
다른 다섯 앱을 합친 통합 앱이나 메뉴 껍데기를 만들지 마.

첫 작업의 핵심 목표는 다음과 같아.
1. 빠른 메모·할 일·등록 바로가기가 있는 독립 홈 화면.
2. 데이터 저장과 카드 순서·표시 설정.
3. 좁은 화면 1열/넓은 화면 다열, 서로 다른 배치 보존.

설명이나 이미지 목업으로 끝내지 말고 가능한 환경에서 실제 파일을 작성하고

필수 기능, 확장 기능, 외부 인증 필요 기능을 구분하고
미완료 항목을 docs/TASKS.md와 docs/PROGRESS.md에 남겨줘.
```

### 0.1 개발 승인 경계

- 일상적인 UI·파일 구조는 합리적인 기본값으로 진행한다. 반복적인 취향 질문으로 멈추지 않는다.
- 비용 발생, 로그인, 민감자료 외부 전송, 위험한 PC 실행, 기존 파일 삭제, 공개 배포는 별도로 확인한다.
- API 키·계정·PC가 없는 상태에서 사용할 수 있는 범위를 먼저 완성한다.
- 기능을 단순히 숨기거나 목업으로 바꾼 뒤 전체 완료라고 보고하지 않는다.
- 숫자·색상·콘텐츠 수·용량 제한은 별도 표시가 없으면 초기 설계값이다. 측정 후 변경 이유를 기록한다.
- 다른 앱과의 연결은 나중에 선택적 공유로 붙일 수 있지만 현재 앱의 필수 선행조건으로 만들지 않는다.

## 1. 제품 목표와 범위

### 1.1 목적

**접으면 메모와 빠른 실행, 펼치면 할 일·일정·집중 타이머를 한눈에 보는 개인 작업 대시보드.**

다른 다섯 앱을 담는 통합 앱이 아니라, 메모·할 일·타이머·바로가기만으로도 가치가 있는 독립 앱이다. 나중에 만든 다른 앱은 선택적 바로가기나 사용자 공유 데이터로 연결한다.

### 1.2 범위

| 구분 | 기능 |
|---|---|
| 필수 | 카드 홈, 메모, 할 일, 단일 집중 타이머, 앱/웹 바로가기, 로컬 일정, 검색, 배치 편집·백업 |
| 확장 | 워크스페이스, 반복 할 일, 홈 위젯, 읽기 전용 연동 카드 |
| 별도 승인 | 시스템 캘린더 접근, 정확한 알림 권한, 실제 외부 API 연동 |
| 제외 | 기본 런처 강제 변경, 다른 앱 내부 데이터 무단 수집, AI API 의무 연결, PC 원격 실행 |

### 1.3 성공 기준

`메모 작성 → 할 일 추가 → 타이머 시작 → 펼쳐서 카드 배치 → 바로가기 실행 → 돌아와 진행 유지 → 재시작 후 자료·배치 복원`이 오프라인 기본 환경에서 가능해야 한다. 외부 웹 바로가기 열기 자체는 네트워크가 필요할 수 있지만 나머지 로컬 기능을 막지 않는다.

## 2. 사용자 흐름과 화면 설계

### 2.1 탐색과 화면

접힌 화면의 기본 하단 메뉴는 `홈 | 기록 | 일정 | 설정`이다. 펼친 화면에서는 탐색 레일과 적응형 그리드를 사용한다.

| ID | 화면 | 주요 행동 | 상태 |
|---|---|---|---|
| HOME-S01 | 대시보드 | 메모·할 일·타이머·바로가기 | 카드가 없으면 추가 안내 |
| HOME-S02 | 배치 편집 | 이동·크기·숨김·저장·취소 | 프로필별 임시 편집 |
| HOME-S03 | 메모 편집·목록 | 생성·수정·고정·삭제·공유 | 저장 상태·휴지통 |
| HOME-S04 | 할 일 | 오늘/예정/완료, 체크 | 기한·날짜 미설정 구분 |
| HOME-S05 | 타이머 상세 | 시작·정지·재개·종료 | 권한 없음·중단·완료 |
| HOME-S06 | 바로가기 편집 | 대상 선택·테스트 열기 | 삭제된 앱·잘못된 URL |
| HOME-S07 | 일정 | 월/목록·추가·수정 | 로컬 저장임을 표시 |
| HOME-S08 | 검색·최근 | 유형 필터·선택 | 검색 없음 |
| HOME-S09 | 설정·백업 | 테마·배치·알림·복원 | 초기화 범위 구분 |

### 2.2 홈 기본 예시

```text
접힘                           펼침
[빠른 메모]                    [빠른 메모          ][집중 타이머]
[오늘 할 일]                   [오늘 할 일        ][오늘 일정  ]
[집중 타이머]                  [바로가기 4개      ][최근 항목  ]
[바로가기 4개]
```

화면이 넓어졌다고 모든 카드 글자·버튼을 비례 확대하지 않는다. 내용을 더 함께 보여주는 방식으로 설계한다.

### 2.3 하루 사용 시나리오

1. 접힌 화면에서 생각난 아이디어를 메모한다.
2. 그 메모를 기반으로 할 일을 만든다. 원래 메모는 삭제하지 않고 참조를 남긴다.
3. 폴드를 펼쳐 왼쪽에 할 일, 오른쪽에 타이머를 둔다.
4. 집중 타이머를 시작하고 외부 작업 앱을 연다.
5. 대시보드로 돌아오면 남은 시간이 실제 경과와 일치한다.
6. 할 일을 완료하고 오늘 기록을 본다.
7. 앱을 닫았다 열어도 배치·내용·완료 이력이 남는다.

## 3. 핵심 기능 상세

### 3.1 대시보드와 카드 시스템

처음 실행하면 네트워크·계정 없이 다음 기본 카드를 보여준다.

| 카드 | 기본 내용 | 누르면 하는 일 |
|---|---|---|
| 빠른 메모 | 짧은 텍스트 입력, 저장 상태 | 새 메모 작성·저장 |
| 오늘 할 일 | 미완료 항목·체크박스 | 추가·완료·상세 |
| 집중 타이머 | 남은 시간·시작/일시정지 | 집중 세션 관리 |
| 바로가기 | 사용자가 고정한 앱/웹 4개 | 선택한 목적지 열기 |
| 최근 항목 | 이 앱에서 편집·연 항목 | 이전 위치 이어보기 |
| 오늘 일정 | 앱 안에 직접 등록한 일정 | 일정 보기·추가 |

- 처음부터 다른 다섯 앱의 미구현 카드 5개로 홈을 채우지 않는다.
- PC 상태·매물·AI 답변·게임 상태 카드는 후속 선택 연동이다. 실제 정보가 없으면 숨기거나 `연동 필요`로 표시한다.
- 카드 ID와 카드 종류를 분리하여 같은 종류를 여러 개 만들 수 있게 설계하되 첫 버전에서는 단순 수량 제한을 허용한다.
- 카드마다 표시 여부, 순서, 제목, 크기, 연결 대상을 저장한다.
- 카드 안의 완료 체크·버튼과 카드 전체 열기 동작이 충돌하지 않게 한다.

### 3.2 접힌 화면·펼친 화면의 레이아웃 편집

- 접힌 화면은 1열, 펼친 화면은 가용 공간에 따라 2열 또는 3열을 기본으로 둔다.
- `좁은 화면 배치`와 `넓은 화면 배치`를 독립 저장한다.
- 카드 길게 누르기→편집 모드→순서/크기/표시 변경→저장/취소의 흐름이다.
- 드래그뿐 아니라 `앞으로`, `뒤로`, `위로`, `아래로` 버튼으로도 이동할 수 있게 한다.
- 편집 도중 접고 펼쳐도 기존 배치가 손상되지 않게 한다. 현재 편집 프로필을 고정하거나 전환 전 저장/취소를 안내한다.
- 카드의 최소 너비·높이와 허용 열 span을 검증한다. 숨긴 카드가 다른 프로필에서 자동 삭제되지 않게 한다.
- 초기화는 선택한 배치만 초기화하며 메모·할 일·바로가기 데이터를 삭제하지 않는다.
- 미리보기 배치는 실제 사용 데이터와 분리한다.

### 3.3 빠른 메모·메모 목록

- 제목 없는 메모를 바로 작성할 수 있고 첫 문장을 제안 제목으로 사용한다.
- 본문, 제목, 고정 여부, 태그, 수정 시각을 저장한다.
- 자동 저장은 약 500ms 입력 디바운스를 초기값으로 하되 화면 이탈 시 미저장 변경을 처리한다.
- 저장 중/저장됨/저장 실패를 표시한다. 실패한 초안을 조용히 버리지 않는다.
- 삭제는 되돌리기 또는 휴지통 정책을 제공한다. 영구 삭제는 별도 확인한다.
- 외부 공유로 받은 텍스트·URL을 새 메모로 저장할 수 있다.
- 이 앱의 메모를 일반 Markdown/텍스트로 공유한다. 2번 리서치 앱의 DB를 직접 쓰지 않는다.

### 3.4 할 일

- 제목, 설명, 선택 마감일, 우선순위, 완료 상태, 수동 순서를 지원한다.
- `오늘`, `예정`, `기한 지남`, `완료` 보기를 제공한다.
- 마감 날짜만 있는 항목을 임의의 자정 알람으로 바꾸지 않는다.
- 완료 체크 즉시 저장하고 되돌리기가 가능하다.
- 완료 항목은 기본 아래로 이동하거나 숨기되 데이터가 삭제되는 것은 아니다.
- 반복 할 일은 후속 단계다. 구현하면 반복 규칙·시간대·완료 회차를 분리한다.
- 초기에는 알림 없이도 체크리스트로 충분히 사용할 수 있어야 한다.

### 3.5 집중 타이머

기본 프리셋은 `25분 집중 / 5분 휴식`과 사용자가 지정하는 단일 타이머다. 자동 다음 세션 시작은 기본 OFF다.

필수 행동:

- 시작, 일시정지, 재개, 종료, 다시 시작.
- 실행 중 남은 시간과 세션 목적/연결 할 일 표시.
- 앱을 나갔다 돌아와도 기준 시각에서 남은 시간을 복원.
- 설정한 종료 시점이 지났으면 음수 시간 대신 종료 상태.
- 완료 이력은 세션당 한 번 저장.
- 프로세스 종료와 기기 재부팅을 구분해 복구 정책 적용.

시간 설계:

- 같은 부팅 세션에서는 monotonic clock 기준 경과시간을 사용한다.
- 지속시간·남은 시간·시작 시각·종료 예정 wall clock·부팅 구분 정보를 필요한 범위로 저장한다.
- 시스템 시간이 바뀌어도 같은 부팅 세션의 타이머 길이가 갑자기 달라지지 않게 한다.
- 재부팅 후 정확히 복구할 수 없으면 `재부팅으로 타이머가 중단됨`과 남은 시간 재개 선택을 제공한다. 임의 완료 이력을 만들지 않는다.
- 정확한 백그라운드 알림이 필요한 경우 공식 알람 방식과 권한을 확인한다. WorkManager를 초 단위 카운트다운 완료 알림으로 사용하지 않는다. [A7][A10]
- 정확 알람 권한이 없으면 대체 알림의 지연 가능성을 표시한다. 권한을 숨겨서 강제 획득하지 않는다.
- 알림 권한을 거절해도 앱 안의 타이머는 사용 가능하다.

### 3.6 앱·웹 바로가기

- 사용자가 선택한 대상의 이름·아이콘·종류·목적지를 저장한다.
- 기본 종류: 웹 URL, 사용자가 고른 실행 가능한 앱, 앱 안의 메모/할 일/타이머.
- ChatGPT·Claude 등은 외부 앱/웹 열기만 제공한다. 자동 질문 입력·답변 읽기를 약속하지 않는다.
- 앱이 삭제됐거나 실행할 수 없으면 `대상을 찾을 수 없습니다`와 수정/웹 대체/삭제를 제공한다.
- 웹은 HTTPS 목적지를 기본값으로 하고 위험하거나 미지원 스킴을 거절한다.
- 다른 앱의 실행 가능 여부 조회는 최소 범위로 설계하며 전체 설치 앱 목록을 무조건 읽지 않는다. [A9]
- 바로가기 열기와 상대 앱 작업 완료는 구분한다.
- API 키·인증 토큰을 URL 쿼리에 저장하지 않는다.

### 3.7 로컬 일정

- 제목, 날짜, 시작/종료 시각, 종일 여부, 메모를 직접 입력한다.
- 시간 지정 일정은 종료가 시작보다 빠르면 저장을 막거나 날짜를 확인한다.
- 종일 일정은 LocalDate 기반으로 관리하여 시간대 변경으로 하루 앞뒤로 밀리지 않게 한다.
- 기본 저장 위치는 이 앱 DB다. Google Calendar 동기화라고 표시하지 않는다.
- 시스템 캘린더 연결은 별도 선택 기능으로 둔다. 권한·읽기 범위·계정·갱신 방식 확인 전 자동 읽지 않는다.
- 실제 동기화가 없으면 앱 밖에서 변경된 일정이 자동 반영된다고 쓰지 않는다.

### 3.8 검색·최근 작업·워크스페이스

- 검색 대상은 이 앱의 메모·할 일·일정·등록 바로가기다.
- 다른 앱 내부 대화·PC 파일·웹 전체를 통합 검색했다고 표시하지 않는다.
- `최근 작업`은 이 앱에서 실제로 연 항목과 사용자가 가져온 항목만 기록한다.
- 최근 목록에 민감한 본문을 노출하지 않는 옵션을 둔다.
- `개인`, `업무`, `개발` 같은 워크스페이스는 후속 기능으로 추가할 수 있다.
- 워크스페이스 전환은 자료 삭제가 아니며, 대시보드 카드 배치와 자료 소속의 범위를 구분한다.

### 3.9 다른 다섯 앱과의 선택적 연결

현재 앱의 필수 기능에 포함하지 않는다. 상대 앱이 실제 존재하고 공유 계약을 지원할 때 추가한다.

| 상대 앱 | 가장 먼저 지원할 연결 | 자동으로 하지 않을 일 |
|---|---|---|
| 1번 AI 작업실 | 질문 작성 바로가기·사용자 공유 결과 고정 | 대화 DB 무단 읽기 |
| 2번 리서치 보드 | 자료 추가 바로가기·보고서 공유 받기 | 원문 자동 전체 수집 |
| 3번 PC 리모컨 | 앱 열기·사용자 공유 상태 스냅샷 | 원격 실행·상시 상태 조회 |
| 5번 도트 게임 | 게임 열기 | 게임 저장 직접 변경 |
| 6번 중고 비교 | 보드 열기·비교표 공유 받기 | 가격 자동 감시를 대신 수행 |

- 처음에는 ACTION_SEND와 사용자가 확인한 공유 텍스트/파일로 연결한다.
- 가져온 스냅샷에는 `가져온 시각·출처 앱·자동 갱신 안 됨`을 표시한다.
- 실제 인증된 읽기 전용 연결을 추가할 때만 실시간 카드라고 부른다.
- 알림 접근권한·접근성 서비스로 다른 앱 내용을 몰래 읽지 않는다.
- 별도 앱이 설치되지 않았으면 카드 추가 화면에서 안내하고, 대시보드 자체 사용을 막지 않는다.

### 3.10 홈 화면 위젯·런처의 범위

- 기본은 일반 앱 안의 대시보드다. 시스템 기본 홈 앱 변경을 요구하지 않는다.
- 작은 메모/할 일/타이머 홈 위젯은 확장 기능이다. 앱 내 카드와 OS 홈 위젯은 별도 구현이다.
- 다른 앱 위젯을 내 화면에 임의로 끼워 넣는 기능은 초기 범위가 아니다.
- 앱 페어 자동 실행·강제 분할 화면·시스템 밝기 제어는 기본 기능에 넣지 않는다.
- 개인 런처로 확장하려면 홈 역할·앱 목록·제스처·설정·복구를 별도 요구사항으로 설계한다.

### 4.2 카드 레지스트리

각 카드 종류는 `typeId`, 지원 크기, 기본 설정, 렌더 함수, 설정 화면, 실제 동작 핸들러를 등록한다. 알 수 없는 typeId를 복원하면 앱 전체 크래시 대신 `지원하지 않는 카드`와 삭제/업데이트 안내를 제공한다.

- 카드 구성과 실제 메모·할 일 데이터는 분리한다.
- 할 일 카드를 숨겨도 할 일은 남는다.
- 같은 메모를 여러 카드에서 가리킬 때 내용은 한 레코드만 수정한다.
- 모든 카드에 네트워크 권한·서비스가 자동으로 붙지 않게 한다.

### 4.3 타이머 상태

```text
IDLE → RUNNING → PAUSED → RUNNING
RUNNING → COMPLETED
RUNNING/PAUSED → CANCELLED
재부팅으로 복구 불명확 → INTERRUPTED
```

- 일시정지 시 remainingMs를 확정하고 재개 시 새 monotonicAnchor를 만든다.
- 완료 이벤트는 timerSessionId로 중복 제거한다.
- 완료와 취소는 집중 이력에 구분한다. 취소를 완료한 집중 시간으로 부풀리지 않는다.
- 타이머 시작 버튼 연속 클릭으로 활성 세션이 여러 개 생기지 않게 한다.
- 사용자가 시스템 시각을 바꿔도 같은 부팅 세션 경과시간을 유지한다.

### 4.4 일정·완료·배치의 시간 처리

- `오늘`은 기기 시간대와 현재 날짜로 계산한다. 백그라운드로 자정이 지나면 복귀 시 다시 계산한다.
- 마감 날짜만 있는 할 일은 날짜 범위로 비교하고 UTC 자정으로 단순 치환하지 않는다.
- 날짜만 있는 일정과 정확 시각 이벤트를 같은 timestamp 하나로 억지 통합하지 않는다.
- 배치 변경은 프로필별 트랜잭션으로 저장하고 저장 취소 때 기존 배치를 그대로 복구한다.
- 초기 배치가 새 버전에서 바뀌어도 기존 사용자 배치를 덮어쓰지 않는다.

## 5. 구현 구조와 연동 계약

### 5.1 Android 기본 기술안

| 영역 | 이 프로젝트의 기본 선택 |
|---|---|
| 언어 | Kotlin |
| 일반 UI | Jetpack Compose + Material 3 |
| 적응형 구성 | Material 3 Adaptive, 필요한 WindowManager 기능 |
| 상태 | ViewModel + Coroutines/Flow + 단방향 흐름 |
| 데이터 | Room, DataStore, 앱 내부 파일 |
| 네트워크 | 필요한 앱에만 검증된 HTTP 클라이언트 |
| 직렬화 | Kotlin Serialization 등 일관된 한 가지 방식 |
| 테스트 | JVM 단위 테스트, Android/Compose UI 테스트 |

UI와 데이터 책임을 분리한다는 원칙을 참고하되, 작은 프로젝트에 불필요한 계층을 늘리지 않는다. [A3]

- `minSdk`는 API 30을 제안값으로 시작하되 실제 단말과 의존성 조건을 확인한다.
- `targetSdk`, `compileSdk`, JDK/Gradle/AGP/Kotlin/Compose/Room 조합은 작업 시점의 안정 버전과 설치 환경을 확인한다.
- 버전을 추정하거나 `latest`/`+`로 두지 않는다. 버전 카탈로그와 잠금 정보를 관리한다.
- preview/alpha는 꼭 필요한 이유와 격리 방법이 있을 때만 채택한다.
- 처음에는 적은 Gradle 모듈로 시작하고 `ui`, `data`, `domain` 등 책임 단위 패키지로 나눈다.
- 기존 저장소의 미커밋 변경과 사용자 파일을 보존한다.
- 다른 언어·웹앱으로 전체 교체하려면 요구사항을 충족하는 이유를 먼저 기록한다. 기본 산출물은 설치 가능한 Android 앱이다.
- 샘플 데이터는 명확한 `예시` 배지를 표시하고 테스트 빌드와 일반 사용 데이터를 분리한다.

### 5.2 구성

```text
07-fold-smart-desk/
├── android/app/
│   ├── dashboard/      # 카드 레지스트리·프로필별 배치
│   ├── notes/
│   ├── todos/
│   ├── calendar/       # 이 앱의 로컬 일정
│   ├── timer/          # 시간 계산·알림·이력
│   ├── shortcuts/
│   └── search/
├── tests/fixtures/
└── docs/
```

`DashboardRepository`, `LayoutEditor`, `TimerController`, `Clock` 추상화, `ShortcutResolver`, `SearchRepository`를 분리한다. 시간 테스트는 실제 대기하지 않고 가짜 Clock으로 검증한다.

### 5.3 바로가기·공유

- 외부 앱 목적지는 사용자가 선택/확인한 실행 가능한 Intent로 저장한다.
- 설치 앱 조회에는 필요한 package/intent visibility만 선언한다. 무조건 QUERY_ALL_PACKAGES를 추가하지 않는다. [A9]
- Intent가 해결되지 않으면 사용자에게 대체 열기·수정을 안내한다.
- 다른 앱으로 연 뒤 돌아왔을 때 이를 결과 완료로 기록하지 않는다.
- 사용자 선택 파일·텍스트 수신은 지원 MIME만 등록하고 입력 크기를 제한한다. [A5]
- 외부 공유로 받은 카드 JSON은 자동 실행하지 않는다. 미리보기·유형 검증·사용자 저장을 거친다.

### 5.4 알람·백그라운드 정책

- 화면 초 단위 카운트다운은 UI가 보이는 동안만 갱신한다. 영속 기준값에서 남은 시간을 계산한다.
- 정확한 타이머 종료 알림을 구현하는 단계에서 대상 Android 버전의 AlarmManager·정확 알람 권한·알림 정책을 확인한다. [A10]
- 정확 알람 접근이 없으면 상태를 명시하고 지연 가능한 대체를 선택한다. 타이머의 로컬 시간 계산을 막지 않는다.
- 반복 WorkManager 작업으로 초 단위 정시 알림을 보장하지 않는다. [A7]
- 재부팅·권한 변경·시간대 변경·앱 업데이트 후 예약 복구 정책을 문서화한다.
- 상시 서비스로 화면을 계속 켜거나 배터리 최적화 해제를 처음부터 강요하지 않는다.

### 5.5 선택 연동의 경계

- 초기 설치에는 1·2·3·5·6번 앱이 전혀 없어도 빈 오류 카드가 쌓이지 않아야 한다.
- `실시간 PC 상태` 같은 카드가 필요해지면 별도 인증된 읽기 전용 계약을 추가한다. URL만 안다고 내부 상태를 읽지 않는다.
- 공유 데이터는 스냅샷이며 최신성·원본 접근 가능 여부를 표시한다.
- 위젯·런처·캘린더 동기화는 각기 별도 기능이며 단순 버튼만으로 구현 완료 처리하지 않는다.

## 8. 폴드 대응·상태 보존·품질 기준

### 8.1 현재 창에 맞춘 화면

기종명이나 물리 해상도 대신 현재 앱 창의 가용 너비·높이와 보고되는 폴딩 정보를 사용한다. 분할 화면과 팝업 창도 고려한다. [A1][A2]

이 앱의 기본 레이아웃 정책은 다음과 같이 설계한다.

| 조건 | 이 앱의 설계 정책 |
|---|---|
| 폭 600dp 미만 | 단일 작업 패널, 목록→상세 탐색 |
| 폭 600~839dp | 각 패널 최소 너비를 확보할 때만 2패널 |
| 폭 840dp 이상 | 2패널 우선, 내용·폰트·키보드에 따라 조정 |
| 폭 1200dp 이상 | 필요할 때 보조 패널 추가, 긴 본문 최대 너비 제한 |
| 낮은 높이·키보드 표시 | 보조 영역을 접고 입력·주요 버튼 접근 보장 |

- 목록 패널 최소 240dp, 읽기·편집 패널 최소 320dp를 초기 설계값으로 둔다.
- 비교 화면의 본문 2개는 각각 최소 320dp를 목표로 하고, 부족하면 탭으로 전환한다.
- 여백·탐색 레일·힌지·큰 글꼴까지 합산해 실제 사용 가능한 공간으로 판단한다.
- `펼쳐짐 = 무조건 3열`로 구현하지 않는다.
- 힌지가 가리거나 화면을 나누는 영역에는 필수 버튼을 배치하지 않는다.
- 기기에서 폴딩 정보가 없으면 창 크기 기준 화면으로 동작한다.
- 반접힘 자세 지원은 실제 정보가 있을 때만 적용한다. 정확한 각도를 추측하지 않는다.
- 회전·크기 변경을 막거나 모든 `configChanges`를 임의 선언하는 방법으로 문제를 숨기지 않는다.
- 커버 화면 전환이 OS/사용자 설정으로 제한되면 앱이 이를 강제로 우회한다고 약속하지 않는다. 다음 활성화 시 상태를 복원한다.

### 8.2 상태는 수명에 따라 분리

UI 상태 저장은 화면 재생성과 프로세스 종료를 구분하여 설계한다. [A4]

| 상태 | 이 앱의 보관 전략 |
|---|---|
| 선택 항목·필터·짧은 편집 상태 | ViewModel 및 SavedState 계층 |
| 사용자 작성 내용·저장 항목 | 로컬 DB에 실제 영속 저장 |
| 대용량 첨부·긴 본문 | 앱 파일/DB에 보관하고 SavedState에는 ID만 |
| 네트워크 실행·전송 | 실행 ID와 서버 상태, 중복 방지 키 |

- 화면 재구성 함수 안에서 결제·외부 호출·작업 실행을 시작하지 않는다.
- 활동 재생성 때문에 같은 저장이나 실행이 반복되지 않게 한다.
- 프로세스 종료 후 미확인 작업을 성공·실패로 임의 확정하지 않는다.
- 비밀값·대용량 문자열·전체 데이터를 Bundle에 넣지 않는다.
- 입력 자동 저장이 있는 경우 저장 중/저장됨/실패 상태를 표현한다.

### 8.3 디자인·접근성

- 한국어 UI, 시스템 테마/밝게/어둡게 선택.
- 간격 토큰 4·8·12·16·24·32dp를 기본값으로 정한다.
- 주요 터치 영역 48dp 이상, 본문 기본 16sp를 설계 목표로 둔다.
- 본문 200% 글자 확대, 시스템 바·키보드 겹침, 가로 화면을 검수한다.
- 화면을 넓히는 대신 목록/본문/작업 도구의 역할을 나눈다.
- 색상만으로 성공·오류·선택을 구분하지 않는다.
- 아이콘에는 접근성 설명을 주고, 반복 장식에는 불필요한 설명을 붙이지 않는다.
- 긴 제목·긴 URL·긴 코드가 전체 레이아웃을 밀어내지 않도록 처리한다.
- 로딩·빈 데이터·검색 결과 없음·권한 거절·오류·부분 성공을 별도로 구현한다.

### 8.4 성능·오류 처리

- 로컬 화면은 외부 연결을 기다리지 않고 먼저 연다.
- 긴 목록은 지연 렌더링·페이지 로딩을 사용하고 검색에는 취소/디바운스를 검토한다.
- 대용량 파일 I/O·DB·해시 연산은 메인 스레드 밖에서 처리한다.
- 화면을 닫으면 불필요한 센서 수집·렌더 루프·타이머·폴링을 중단한다.
- 네트워크 오류에는 재시도 가능 여부와 데이터 보존 여부를 보여준다.
- 사용자가 취소한 동작을 오류로 반복 알림하지 않는다.
- 저장 공간 부족 시 기존 정상 데이터를 유지하고 저장 실패를 알린다.
- 성능 수치는 목표와 측정값을 구분하고, 기기·OS·데이터량·빌드 종류를 보고한다.

## 9. 저장·백업·보안·독립 실행 규칙

### 9.1 데이터의 진실성

- 이 앱만의 DB·설정·파일 디렉터리를 사용한다. 다른 앱의 DB를 직접 읽지 않는다.
- ID는 충돌 방지 가능한 방식으로 생성하고, 시각은 UTC 저장/기기 시간대 표시를 기본값으로 둔다.
- 날짜만 확인된 정보는 날짜 정밀도를 보존하고 임의 시각을 붙이지 않는다.
- 알 수 없는 값은 `null`/`UNKNOWN`으로 표현한다. 미확인을 0·정상·무료로 치환하지 않는다.
- 금액은 정수 또는 정밀 십진수로 저장하며 통화를 분리한다.
- 삭제·초기화·설정 재설정의 영향을 분리해 설명한다.
- 스키마 변경에는 마이그레이션을 작성한다. 사용자 DB를 지우는 마이그레이션은 기본 금지다.
- DB와 첨부 파일은 참조 무결성을 관리한다. 공유 중인 첨부의 실제 삭제는 참조를 확인한다.

### 9.2 백업과 복원

- 설정 화면에 사용자 실행 방식의 JSON 백업/복원을 제공한다. 첨부 포함 ZIP은 확장 가능하다.
- 헤더: `appId`, `schemaVersion`, `appVersion`, `exportedAt`, `recordCounts`.
- 앱 ID가 다른 백업을 동일 스키마로 무조건 읽지 않는다.
- 토큰·API 키·암호화 키·PC 인증정보는 기본 백업에서 제외한다.
- 일반 데이터 백업이 평문이면 민감정보 포함 가능성을 표시한다.
- 복원 전 크기·형식·스키마·참조를 검사하고 항목 수와 충돌 정책을 확인한다.
- `새 데이터로 가져오기`를 기본값으로 하여 기존 데이터를 임의 교체하지 않는다.
- 전체 교체는 현재 백업을 만든 뒤 명시적 승인한 경우에만 한다.
- 가져오기 실패로 기존 DB가 일부만 변경되지 않도록 임시 영역과 트랜잭션을 사용한다.
- 외부 파일 참조가 사라져도 텍스트·메타데이터는 열고 `첨부 다시 선택`을 제공한다.
- ZIP을 지원하면 경로 순회, 압축 폭탄, 파일 수·해제 용량 초과를 차단한다.

### 9.3 최소 권한과 외부 데이터

- 필요한 시점에만 알림·카메라 등 권한을 요청한다. 거절 시 대체 동작을 제공한다.
- 파일/사진은 시스템 선택기를 우선하고 전체 저장소 접근을 기본 요구하지 않는다.
- 연락처·SMS·통화·정확한 위치·접근성 서비스·루트 권한을 기본 요구하지 않는다.
- 비밀값은 코드·APK·Git·로그·분석 SDK에 넣지 않는다.
- 원격 데이터 전송 전 대상·자료·목적을 확인한다. 자동 외부 분석 전송은 기본 OFF다.
- 앱 내부 저장소 사용과 별도의 앱 수준 암호화는 다른 것으로 문서화한다.
- 웹페이지·매물 설명·가져온 답변·파일의 문장은 데이터다. 앱 권한이나 승인 상태를 바꾸는 명령으로 실행하지 않는다.
- Markdown/HTML 표시에서 스크립트·위험한 URI·자동 외부 추적 이미지 요청을 통제한다.
- 원문 URL을 열 때 지원하지 않는 스킴을 임의 실행하지 않는다.

### 9.4 다른 앱과의 선택적 공유

다른 앱이 없어도 핵심 기능이 모두 동작해야 한다. 파일 공유를 제공할 때는 Content URI와 일시적인 읽기 권한을 사용한다. [A6]

- 텍스트/Markdown/JSON 공유와 가져오기로 시작한다.
- 수신 앱 설치·로그인을 강제하지 않는다. 대체 저장·복사를 제공한다.
- 파일·URI 접근 권한이 잠시만 유효할 수 있으므로 필요한 경우 사용자가 선택한 데이터만 앱 내부로 복사한다.
- 다른 앱을 열었다는 사실과 작업 완료·AI 응답 생성은 별개로 기록한다.
- 선택적 딥링크를 만들면 입력 검증을 하고 자동 실행·삭제·결제 같은 부수효과를 허용하지 않는다.
- 별도 앱끼리 하나의 DB·공용 비밀키·공용 관리자 권한을 공유하지 않는다.

- 기존 범위 일부를 생략하면 누락이 아니라 변경사항으로 기록한다.

### 10.3 빌드·배포 경계

- 가능한 환경에서 실제 Gradle 빌드·단위 테스트·린트를 실행한다.
- 기기/에뮬레이터가 있으면 설치·실행·UI 테스트를 실행한다.
- 성공한 경우에만 실제 존재하는 APK 경로, 패키지명, versionCode/versionName, 체크섬을 보고한다.
- JDK/SDK/네트워크 제한 때문에 실행하지 못했으면 시도한 명령·오류·필요 조건을 적는다.
- 서명키와 비밀번호는 공개하지 않는다. 스토어 업로드·외부 공개·Git 원격 푸시는 별도 요청 전 하지 않는다.
- 이 문서는 제작 명세다. 문서를 만든 것과 앱이 구현·빌드된 것을 혼동하지 않는다.

### 10.4 작업 종료 때 보고할 형식

```text
앱 번호와 이름:
현재 단계:
이번에 실제 구현한 기능:
수정한 주요 파일:
실행한 빌드·테스트 명령과 결과:
실제 APK 경로 또는 미생성 이유:
실기기·외부 서비스 검증 여부:
미구현·미검증·외부 설정 필요 항목:
다음 단계와 바로 실행할 작업:
```

### 10.5 다음 대화에서 이어갈 명령

```text
이 프로젝트의 docs/SPEC.md, TASKS.md, PROGRESS.md, DECISIONS.md,
TEST_REPORT.md를 먼저 읽고 현재 앱 하나의 개발을 이어가줘.
기존 프로젝트를 초기화하거나 다른 앱 기능을 섞지 마.
이전 단계의 빌드 오류와 검증 실패부터 해결한 뒤 다음 미완료 단계를 진행해줘.
외부 계정이 없어 막힌 기능과, 계속 만들 수 있는 로컬 기능을 구분해줘.
실제 코드 작성·저장·오류 처리·테스트까지 연결하고 진행 문서를 갱신해줘.
```

### 10.6 화면만 만들어졌을 때 수정 명령

```text
현재 화면이 아니라 이 명세의 완료 기준을 확인해줘.
버튼별 실제 동작, 영속 저장, 재실행 복원, 오류 처리,
접기·펼치기 상태 유지부터 완성해줘.
새 화면을 늘리지 말고 현재 단계의 사용자 흐름을 끝까지 작동시켜줘.
테스트 데이터와 실연동을 분리해서 검증 결과를 보고해줘.
```
