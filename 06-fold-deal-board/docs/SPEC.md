## 0. Claude에게 전달할 작업 명령

```text

이 문서를 끝까지 읽고 실제 Android 앱 개발을 시작해줘.
다른 다섯 앱을 합친 통합 앱이나 메뉴 껍데기를 만들지 마.

필수 기능, 확장 기능, 외부 인증 필요 기능을 구분하고
미완료 항목을 docs/TASKS.md와 docs/PROGRESS.md에 남겨줘.
실제 APK가 생성된 경우에만 파일 경로를 알려줘.
```

### 0.1 개발 승인 경계

- 일상적인 UI·파일 구조는 합리적인 기본값으로 진행한다. 반복적인 취향 질문으로 멈추지 않는다.
- 비용 발생, 로그인, 민감자료 외부 전송, 위험한 PC 실행, 기존 파일 삭제, 공개 배포는 별도로 확인한다.
- API 키·계정·PC가 없는 상태에서 사용할 수 있는 범위를 먼저 완성한다.
- 기능을 단순히 숨기거나 목업으로 바꾼 뒤 전체 완료라고 보고하지 않는다.
- 숫자·색상·콘텐츠 수·용량 제한은 별도 표시가 없으면 초기 설계값이다. 측정 후 변경 이유를 기록한다.
- 다른 앱과의 연결은 나중에 선택적 공유로 붙일 수 있지만 현재 앱의 필수 선행조건으로 만들지 않는다.

## 1. 제품 목표와 범위

### 1.1 목적

**여러 중고 플랫폼의 매물을 한곳에 직접 모아 같은 사양끼리 가격·상태·확인일을 비교하는 개인 구매 검토 도구.**

처음부터 전체 사이트를 자동 수집하는 앱이 아니다. 사용자가 저장한 자료로 실제 쓸 수 있는 비교판을 먼저 만들고, 자동 갱신은 허용된 데이터 경로가 확인된 경우에만 추가한다.

| 범위 | 기능 |
|---|---|
| 필수 | 링크 공유·수동 입력, 사양·상태, 이미지 첨부, 보드, 필터, 2~4개 비교, 관측 이력, 예산·체크리스트 |
| 알림 단계 | 새로 기록한 가격에 대한 조건 평가, 알림/앱 내 기록 |
| 선택 확장 | 허용된 API/피드 갱신, OCR·AI 필드 제안 |
| 제외 | 차단 우회 수집, 자동 구매·송금·판매자 연락, 전체 시장 최저가 보장 |

### 1.2 중요한 제품 원칙

`판매자가 올린 가격`, `협상 제안`, `사용자가 확인한 거래가격`을 섞지 않는다. 데이터가 없는 상태는 좋은 상태가 아니다. AI가 제안한 사양은 사람이 확인하기 전까지 확정 사양이 아니다.

### 1.3 성공 흐름

`매물 5개 저장 → 모델/RAM/용량 필터 → 3개 비교 → 상태 미확인 항목 확인 → 가격 변경 기록 → 조건 충족 알림 → 비교 결과 내보내기`가 다른 앱 없이 동작한다.

## 2. 사용자 흐름과 화면 설계

### 2.1 화면 목록

| ID | 화면 | 주요 행동 | 상태·예외 |
|---|---|---|---|
| MKT-S01 | 보드·매물 목록 | 추가, 검색, 정렬, 관심/제외 | 아직 저장한 매물 없음 |
| MKT-S02 | 공유/직접 추가 | URL·가격·모델·이미지 | 가격 미확인으로도 저장 가능 |
| MKT-S03 | 매물 상세 | 사양·상태·원본 열기·관측 기록 | 최신성 경고·삭제된 링크 |
| MKT-S04 | 비교 | 2~4개 선택, 차이 강조 | 사양 미일치·미확인 표시 |
| MKT-S05 | 가격 이력 | 관측/협상/실거래 구분 | 기록 1개면 단일 지점 |
| MKT-S06 | 조건·알림 | 모델·예산·날짜·상태 설정 | 자동 갱신 없으면 수동 기준 표시 |
| MKT-S07 | 구매 체크리스트 | 질문·확인·메모 | 판매자 주장과 직접 확인 구분 |
| MKT-S08 | 내보내기·백업 | MD/CSV/JSON | 개인정보·사진 포함 선택 |

### 2.2 비교표 행동

- 왼쪽 항목 열과 매물 이름을 가능하면 고정하고 본문은 가로/세로 스크롤한다.
- 큰 글꼴에서 고정 열 때문에 본문 폭이 부족하면 매물별 핵심 차이 카드로 대체한다.
- `다른 항목만 보기`, `미확인 포함`, `가격 기준/총비용 기준`을 제공한다.
- 등록일과 마지막 확인일 필터를 별도로 둔다.
- 비교 매물 삭제/판매 완료 때 이전 비교 기록을 표시하되 현재 유효 매물과 구분한다.

```text
접힘: [보드] [조건] → 매물 카드 → 비교 탭/가로표
펼침:
[모델·RAM·용량·예산·확인일]
┌─────────────┬──────────┬──────────┬──────────┐
│ 항목        │ 매물 A   │ 매물 B   │ 매물 C   │
│ 판매가      │          │          │          │
│ 배송·총비용 │          │          │          │
│ RAM / 용량  │          │          │          │
│ 내부 화면   │          │          │          │
│ 확인일      │          │          │          │
└─────────────┴──────────┴──────────┴──────────┘
[확인할 차이] [질문 복사] [비교 저장·내보내기]
```

### 2.3 입력 세부 규칙

- `70만`, `700,000원`, `700000` 같은 입력은 확인 가능한 경우 정규화하고 원문을 보존한다.
- `가격 협의`, `일괄`, `개당`, `보증금` 등의 표현을 단순 판매가로 강제 변환하지 않는다.
- RAM `16GB`와 저장공간 `512GB`, RAM `16×2`와 총 32GB를 서로 다른 필드로 다룬다.
- 스크린샷은 단순 첨부부터 구현한다. OCR/AI 추출을 켠 경우 후보값·원문 위치·확인 상태를 표시한다.

## 3. 핵심 기능 상세

### 3.1 목적

여러 매물 페이지를 오가면서 기억으로 비교하지 않도록, **내가 저장한 매물의 가격·사양·상태·확인일을 한 화면에서 비교**한다.

### 3.2 첫 버전의 자료 입력

- 번개장터, 중고나라, 당근 등에서 사용자가 직접 공유한 링크 저장.
- 가격·모델·상태를 직접 입력하거나 수정.
- 사용자가 선택한 스크린샷 첨부.
- 설명 문구 붙여넣기.
- 입력한 데이터의 출처를 `직접 입력`, `설명에서 가져옴`, `허용된 연동`, `AI 제안`으로 구분.

사이트별 비공개 API가 있다고 가정하지 않는다. 로그인·차단·이용 조건 문제가 있으면 우회 구현하지 말고 수동 저장 기능을 유지한다.

### 3.3 공통 필드

| 항목 | 요구사항 |
|---|---|
| 플랫폼·원본 링크 | 원본으로 돌아갈 수 있어야 함 |
| 제품 분류 | 휴대폰 / PC 부품 / 노트북 / 태블릿 / 기타 |
| 제조사·모델 | 정규화 이름과 판매자 원문을 함께 보존 |
| 판매가 | 원화 정수, 미확인 값과 0원을 구분 |
| 배송비 | 알려진 경우만 입력, 포함·별도·미확인 구분 |
| 거래 지역 | 사용자가 입력, 정밀 위치 권한 불필요 |
| 등록일 | 실제 확인값, 미확인 허용 |
| 마지막 가격 확인일 | 관측 시각 기록 |
| 거래 상태 | 판매 중 / 예약 / 판매 완료 / 확인 불가 |
| 상태 설명 | 흠집, 잔상, 수리, 배터리 등 |
| 가격 이력 | 이전 값을 덮어쓰지 않고 관측값 누적 |
| 사용자 평가 | 관심 / 보류 / 제외 / 구매 완료 |
| 메모·첨부 | 질문, 협상 내용, 스크린샷 |

판매자 연락처 같은 개인정보는 필요할 때만 사용자가 직접 입력하게 하며 기본 수집하지 않는다.

### 3.4 분류별 사양

휴대폰:

- 정확한 모델·세대·파생 모델.
- RAM, 저장공간, 색상.
- 내수/해외 등 확인된 제품 구분.
- 외부·내부 화면 상태.
- 잔상, 힌지, 수리 이력, 배터리 상태.
- 구성품·보증·판매자가 주장한 내용과 직접 확인한 내용을 구분.

PC 부품:

- CPU/GPU/SSD/RAM 등 부품 구분.
- GPU VRAM, SSD 용량·인터페이스·사용량, RAM 용량·개수·규격·클럭.
- 정확한 세부 모델명.
- 보증·영수증·사용 이력.

**Fold SE와 Fold6처럼 이름이 비슷한 제품을 같은 모델로 자동 합치지 않는다. RAM과 저장공간을 서로 다른 필드로 다룬다.**

### 3.5 비교 화면

접힌 화면:

- 카드 목록.
- 2~4개 매물 선택.
- 핵심 차이 카드 또는 가로 스크롤 표.

펼친 화면:

```text
필터: 모델 | RAM | 용량 | 가격 | 상태 | 등록일 | 확인일
┌─────────┬─────────┬─────────┬─────────┐
│ 비교항목│ 매물 A  │ 매물 B  │ 매물 C  │
├─────────┼─────────┼─────────┼─────────┤
│ 가격    │         │         │         │
│ RAM     │         │         │         │
│ 용량    │         │         │         │
│ 화면상태│         │         │         │
│ 수리이력│         │         │         │
│ 확인일  │         │         │         │
└─────────┴─────────┴─────────┴─────────┘
```

- 차이가 있는 항목을 강조한다.
- 미확인 값을 좋은 상태로 간주하지 않는다.
- `같은 조건만 비교` 옵션을 제공한다.
- 배송비가 모르면 총비용도 미확인으로 표시한다. 임의로 무료배송 처리하지 않는다.

### 3.6 가격 판단

초기에는 복잡한 AI 점수보다 투명한 비교를 우선한다.

- 같은 조건의 **저장된 매물 기준** 최저가·중앙값·표본 수 표시.
- 전체 시장 최저가나 실제 거래 완료 가격이라고 표현하지 않는다.
- 게시 가격과 협상·실거래 가격을 구분한다.
- 표본이 적으면 `표본 부족` 표시.
- 등록일 또는 관측 시각이 오래된 매물은 기본 비교에서 분리할 수 있게 한다.
- 사용자 예산 대비 차액 계산.
- `사양 일치`, `상태 미확인`, `수리 이력 확인 필요` 등 근거 있는 체크 포인트 제공.
- AI 추천은 선택 기능이며 추천 이유·사용 데이터·미확인 사항을 함께 표시한다.

### 3.7 가격 알림

**수동 데이터 모드**:

- 사용자가 가격을 수정하거나 새 관측값을 입력하면 조건을 평가한다.
- 알림에 `직접 기록한 가격 기준`임을 표시한다.
- 데이터가 갱신되지 않으면 가격이 내려갔는지 알 수 없다고 명확히 안내한다.

**자동 데이터 모드 — 후속 확장**:

- 공식 API, 허용된 피드 또는 사용 권한을 검증한 수집 어댑터가 있는 경우에만 켠다.
- 수집 주기, 지원 플랫폼, 실패 상태, 마지막 성공 시각을 표시한다.
- 최초에는 새로고침 버튼 중심으로 시작하고, 자동 확인은 사용자가 선택한다.
- Android 주기 작업은 정확한 시각의 실시간 감시가 아니며 WorkManager의 주기·전력 제약을 따른다. [A7]
- 예시 기본 주기는 6시간. 짧은 주기로 바꿔도 즉시성이나 실행 시각을 보장하지 않는다.
- 동일 관측값으로 알림이 반복 발생하지 않게 한다.

조건 예시:

```text
정확한 모델 = Galaxy Z Fold 계열의 사용자가 선택한 세부 모델
RAM >= 사용자 입력값
저장공간 >= 사용자 입력값
가격 <= 사용자 예산
거래 상태 = 판매 중
관측값이 허용된 최신성 범위 안에 있음
```

알림은 원본 링크 열기까지만 제공한다. 자동 구매·송금·메시지 전송은 하지 않는다.

### 3.8 매물 비교 앱 완료 기준

- 실제 사용자가 입력한 5개 매물을 저장·수정·삭제·비교할 수 있다.
- 정확히 같은 사양끼리 비교할 수 있다.
- 미확인 필드가 0이나 정상으로 둔갑하지 않는다.
- 가격 수정 이력이 보존된다.
- 조건에 새로 진입한 가격 관측에 대해 알림이 한 번 발생한다.
- 자동 수집을 구현하지 않았다면 `자동 추적 중`이라고 표시하지 않는다.

### 3.9 후보 보드와 비교 세션

- 관심 폴더 예: `휴대폰`, `노트북`, `SSD`, `내가 만든 보드`.
- 하나의 보드에 예산·필수 조건·선호 조건·제외 조건을 저장한다.
- 필수 조건이 미확인이면 `조건 충족`으로 통과시키지 않고 `확인 필요`로 둔다.
- 비교 세션에는 선택한 2~4개 매물, 비교 기준, 사용한 가격 관측 시각을 저장한다.
- 목록의 가격이 새로 바뀌면 비교 세션에 `새 관측값 있음`을 표시하고 갱신 여부를 선택한다.
- 협상 가격은 게시 가격을 덮어쓰지 않는 별도 기록이다.
- 구매 완료는 사용자가 직접 지정하며 자동 구매·결제를 실행하지 않는다.

### 3.10 구매 전 확인 메모

- 화면 상태, 수리 이력, 배터리, 구성품, 보증, 직거래 가능 여부를 질문 목록으로 만든다.
- 폴더블 휴대폰은 내부/외부 화면·힌지·보호필름 상태를 분리한다.
- PC 부품은 정확한 세부 모델·규격·사용량·보증 정보를 분리한다.
- 판매자 주장, 사용자의 실제 확인, AI 추출 제안을 각각 구분한다.
- 질문은 복사/공유까지만 제공한다. 판매자에게 자동 전송하지 않는다.
- 가격이 낮다는 이유만으로 안전한 거래 또는 정상 제품이라고 보증하지 않는다.

### 4.2 비교 집계의 정의

- 집계 대상은 선택 보드에서 정확한 모델·요구 사양·거래 상태·최신성 조건을 만족한 매물이다.
- 각 매물의 유효한 최신 게시가격 관측 1개만 사용한다. 한 매물의 과거 가격 10개를 표본 10개로 세지 않는다.
- 판매 완료 매물은 기본 현재 구매 후보에서 제외한다. 게시가격을 실거래가로 추정하지 않는다.
- 배송비 미확인은 `총비용 미확인`이다. 직거래 선택으로 배송이 없는 경우에만 0원으로 확정할 수 있다.
- 통화가 다르면 자동 합산하지 않는다. 환율 기능은 별도 출처·확인일을 갖는 후속 기능이다.
- 최저가/중앙값/범위 옆에 `저장한 매물 N개 기준`을 표시한다.
- N<3은 초기 정책상 표본 부족으로 표시하되 N>=3도 시장 대표성이 있다고 보장하지 않는다.

### 4.3 계산 예시 — 테스트용 가상 데이터

동일 모델·RAM·용량·상태 조건을 충족한 3개 매물의 총비용이 605,000원, 620,000원, 625,000원이라고 가정한다.

```text
저장 표본 수 = 3
저장 표본 최저 총비용 = 605,000원
저장 표본 중앙값 = 620,000원
예산 650,000원 대비 A 잔액 = 45,000원
```

이는 실제 매물이나 시세가 아닌 계산 검수용 예시다. 배송비를 모르는 네 번째 매물은 총비용 집계에서 제외하고 제외 이유를 표시한다.

### 4.4 조건 평가와 중복 알림

`MATCH / NO_MATCH / UNKNOWN`의 3값 논리를 사용한다.

- 필수 모델·가격·사양이 미확인이면 UNKNOWN이다.
- 새 관측값이 유효 기간 안이고 조건을 만족했을 때만 MATCH다.
- 기본은 NO_MATCH/UNKNOWN→MATCH 전환 때 한 번 알린다.
- 규칙 생성 당시 기존 매물의 알림 여부는 설정으로 선택한다. 초기 기본값은 과거 데이터 소급 알림 OFF다.
- 같은 ruleVersion+listingId+observationId 평가를 중복 저장·발송하지 않는다.
- 조건을 계속 만족한 채 같은 가격이 재확인되면 기본적으로 다시 알리지 않는다.
- `추가 X원 하락 시 재알림`은 별도 옵션이며 마지막 알림 가격을 기준으로 계산한다.
- 권한이 없으면 앱 내 알림 이력은 남기고 시스템 알림을 보냈다고 기록하지 않는다.
- 수동 가격 입력에 따른 결과를 자동 수집 발견으로 표시하지 않는다.

## 5. 구현 구조와 연동 계약

### 5.1 Android 기본 기술안

| 영역 | 이 프로젝트의 기본 선택 |
|---|---|
| 언어 | Kotlin |
| 일반 UI | Jetpack Compose + Material 3 |
| 적응형 구성 | Material 3 Adaptive, 필요한 WindowManager 기능 |

| 직렬화 | Kotlin Serialization 등 일관된 한 가지 방식 |
| 테스트 | JVM 단위 테스트, Android/Compose UI 테스트 |

UI와 데이터 책임을 분리한다는 원칙을 참고하되, 작은 프로젝트에 불필요한 계층을 늘리지 않는다. [A3]

- `minSdk`는 API 30을 제안값으로 시작하되 실제 단말과 의존성 조건을 확인한다.
- `targetSdk`, `compileSdk`, JDK/Gradle/AGP/Kotlin/Compose/Room 조합은 작업 시점의 안정 버전과 설치 환경을 확인한다.
- 버전을 추정하거나 `latest`/`+`로 두지 않는다. 버전 카탈로그와 잠금 정보를 관리한다.
- preview/alpha는 꼭 필요한 이유와 격리 방법이 있을 때만 채택한다.
- 처음에는 적은 Gradle 모듈로 시작하고 `ui`, `data`, `domain` 등 책임 단위 패키지로 나눈다.
- 기존 저장소의 미커밋 변경과 사용자 파일을 보존한다.
- 다른 언어·웹앱으로 전체 교체하려면 요구사항을 충족하는 이유를 먼저 기록한다. 기본 산출물은 설치 가능한 Android 앱이다.
- 샘플 데이터는 명확한 `예시` 배지를 표시하고 테스트 빌드와 일반 사용 데이터를 분리한다.

### 5.2 독립 구조

```text
06-fold-deal-board/
```

`ListingRepository`, `SpecNormalizer`, `ComparisonCalculator`, `WatchEvaluator`, `ExportService`를 분리한다. 가격 비교 계산기는 네트워크 없이 테스트할 수 있어야 한다.

### 5.3 자동 갱신 어댑터 계약

후속 어댑터의 결과는 다음 정보를 제공해야 한다.

```text
platform, listingId, sourceUrl, observedAt, fetchStatus,
priceValue?, shippingValue?, listingState?, publishedAt?,
fieldEvidence[], warnings[], sourcePolicyVersion
```

- 플랫폼별 공식 API·피드·사용 권한·허용 범위를 확인한 것만 등록한다.
- 사이트 이름만 보고 비공개 API 경로·인증 방법을 만들어내지 않는다.
- CAPTCHA·로그인·차단을 만나면 실패 상태로 남기고 직접 입력/원본 열기를 제공한다.
- 수집 실패는 가격 관측을 0원 또는 판매 완료로 생성하지 않는다.
- 출처별 마지막 시도/마지막 성공/지원 필드·연동 방식 표시를 분리한다.
- 스크랩 본문과 모델 제안은 필드별 원문 근거를 남기고 사용자 확인을 받는다.

### 5.4 알림과 백그라운드

- 수동 모드는 사용자가 가격을 갱신한 직후 로컬 평가한다. 실시간 추적 문구를 쓰지 않는다.
- 허용된 자동 어댑터가 있을 때만 사용자가 자동 확인을 켤 수 있다.
- 자동 확인 기본 제안은 6시간이며 WorkManager 등 OS 제약에 따른 지연 가능성을 표시한다. 정확한 시간의 감시를 보장하지 않는다. [A7]
- 앱 내 새로고침도 동시 중복 요청·호출 제한·취소를 처리한다.
- 모든 매물을 매초 폴링하거나 상시 서비스를 기본 추가하지 않는다.
- 알림에는 원본 열기와 상세 확인만 둔다. 구매·송금·자동 메시지는 없다.

### 5.5 내보내기

- MD: 비교표·조건·관측 시각·원본 URL·미확인 항목.
- CSV: 문자열 따옴표·줄바꿈 이스케이프, `= + - @`로 시작하는 외부 문자열의 수식 실행 방지 정책.
- JSON: 구조화 복원, 가격/배송 미확인·통화·출처 보존.
- 판매자 연락처·계좌·대화 캡처는 기본 자동 수집·공유하지 않는다.

## 8. 폴드 대응·상태 보존·품질 기준

### 8.1 현재 창에 맞춘 화면

기종명이나 물리 해상도 대신 현재 앱 창의 가용 너비·높이와 보고되는 폴딩 정보를 사용한다. 분할 화면과 팝업 창도 고려한다. [A1][A2]

이 앱의 기본 레이아웃 정책은 다음과 같이 설계한다.

| 조건 | 이 앱의 설계 정책 |
|---|---|
| 폭 600dp 미만 | 단일 작업 패널, 목록→상세 탐색 |
| 폭 600~839dp | 각 패널 최소 너비를 확보할 때만 2패널 |
| 폭 840dp 이상 | 2패널 우선, 내용·폰트·키보드에 따라 조정 |
| 폭 1200dp 이상 | 필요할 때 보조 패널 추가, 긴 본문 최대 너비 제한 |
| 낮은 높이·키보드 표시 | 보조 영역을 접고 입력·주요 버튼 접근 보장 |

- 목록 패널 최소 240dp, 읽기·편집 패널 최소 320dp를 초기 설계값으로 둔다.
- 비교 화면의 본문 2개는 각각 최소 320dp를 목표로 하고, 부족하면 탭으로 전환한다.
- 여백·탐색 레일·힌지·큰 글꼴까지 합산해 실제 사용 가능한 공간으로 판단한다.
- `펼쳐짐 = 무조건 3열`로 구현하지 않는다.
- 힌지가 가리거나 화면을 나누는 영역에는 필수 버튼을 배치하지 않는다.
- 기기에서 폴딩 정보가 없으면 창 크기 기준 화면으로 동작한다.
- 반접힘 자세 지원은 실제 정보가 있을 때만 적용한다. 정확한 각도를 추측하지 않는다.
- 회전·크기 변경을 막거나 모든 `configChanges`를 임의 선언하는 방법으로 문제를 숨기지 않는다.
- 커버 화면 전환이 OS/사용자 설정으로 제한되면 앱이 이를 강제로 우회한다고 약속하지 않는다. 다음 활성화 시 상태를 복원한다.

### 8.2 상태는 수명에 따라 분리

UI 상태 저장은 화면 재생성과 프로세스 종료를 구분하여 설계한다. [A4]

| 상태 | 이 앱의 보관 전략 |
|---|---|
| 선택 항목·필터·짧은 편집 상태 | ViewModel 및 SavedState 계층 |
| 사용자 작성 내용·저장 항목 | 로컬 DB에 실제 영속 저장 |
| 대용량 첨부·긴 본문 | 앱 파일/DB에 보관하고 SavedState에는 ID만 |
| 네트워크 실행·전송 | 실행 ID와 서버 상태, 중복 방지 키 |

- 화면 재구성 함수 안에서 결제·외부 호출·작업 실행을 시작하지 않는다.
- 활동 재생성 때문에 같은 저장이나 실행이 반복되지 않게 한다.
- 프로세스 종료 후 미확인 작업을 성공·실패로 임의 확정하지 않는다.
- 비밀값·대용량 문자열·전체 데이터를 Bundle에 넣지 않는다.
- 입력 자동 저장이 있는 경우 저장 중/저장됨/실패 상태를 표현한다.

### 8.3 디자인·접근성

- 한국어 UI, 시스템 테마/밝게/어둡게 선택.
- 간격 토큰 4·8·12·16·24·32dp를 기본값으로 정한다.
- 주요 터치 영역 48dp 이상, 본문 기본 16sp를 설계 목표로 둔다.
- 본문 200% 글자 확대, 시스템 바·키보드 겹침, 가로 화면을 검수한다.
- 화면을 넓히는 대신 목록/본문/작업 도구의 역할을 나눈다.
- 색상만으로 성공·오류·선택을 구분하지 않는다.
- 아이콘에는 접근성 설명을 주고, 반복 장식에는 불필요한 설명을 붙이지 않는다.
- 긴 제목·긴 URL·긴 코드가 전체 레이아웃을 밀어내지 않도록 처리한다.
- 로딩·빈 데이터·검색 결과 없음·권한 거절·오류·부분 성공을 별도로 구현한다.

### 8.4 성능·오류 처리

- 로컬 화면은 외부 연결을 기다리지 않고 먼저 연다.
- 긴 목록은 지연 렌더링·페이지 로딩을 사용하고 검색에는 취소/디바운스를 검토한다.
- 대용량 파일 I/O·DB·해시 연산은 메인 스레드 밖에서 처리한다.
- 화면을 닫으면 불필요한 센서 수집·렌더 루프·타이머·폴링을 중단한다.
- 네트워크 오류에는 재시도 가능 여부와 데이터 보존 여부를 보여준다.
- 사용자가 취소한 동작을 오류로 반복 알림하지 않는다.
- 저장 공간 부족 시 기존 정상 데이터를 유지하고 저장 실패를 알린다.
- 성능 수치는 목표와 측정값을 구분하고, 기기·OS·데이터량·빌드 종류를 보고한다.

## 9. 저장·백업·보안·독립 실행 규칙

### 9.1 데이터의 진실성

- 이 앱만의 DB·설정·파일 디렉터리를 사용한다. 다른 앱의 DB를 직접 읽지 않는다.
- ID는 충돌 방지 가능한 방식으로 생성하고, 시각은 UTC 저장/기기 시간대 표시를 기본값으로 둔다.
- 날짜만 확인된 정보는 날짜 정밀도를 보존하고 임의 시각을 붙이지 않는다.
- 알 수 없는 값은 `null`/`UNKNOWN`으로 표현한다. 미확인을 0·정상·무료로 치환하지 않는다.
- 금액은 정수 또는 정밀 십진수로 저장하며 통화를 분리한다.
- 삭제·초기화·설정 재설정의 영향을 분리해 설명한다.
- 스키마 변경에는 마이그레이션을 작성한다. 사용자 DB를 지우는 마이그레이션은 기본 금지다.
- DB와 첨부 파일은 참조 무결성을 관리한다. 공유 중인 첨부의 실제 삭제는 참조를 확인한다.

### 9.2 백업과 복원

- 설정 화면에 사용자 실행 방식의 JSON 백업/복원을 제공한다. 첨부 포함 ZIP은 확장 가능하다.
- 헤더: `appId`, `schemaVersion`, `appVersion`, `exportedAt`, `recordCounts`.
- 앱 ID가 다른 백업을 동일 스키마로 무조건 읽지 않는다.
- 토큰·API 키·암호화 키·PC 인증정보는 기본 백업에서 제외한다.
- 일반 데이터 백업이 평문이면 민감정보 포함 가능성을 표시한다.
- 복원 전 크기·형식·스키마·참조를 검사하고 항목 수와 충돌 정책을 확인한다.
- `새 데이터로 가져오기`를 기본값으로 하여 기존 데이터를 임의 교체하지 않는다.
- 전체 교체는 현재 백업을 만든 뒤 명시적 승인한 경우에만 한다.
- 가져오기 실패로 기존 DB가 일부만 변경되지 않도록 임시 영역과 트랜잭션을 사용한다.
- 외부 파일 참조가 사라져도 텍스트·메타데이터는 열고 `첨부 다시 선택`을 제공한다.
- ZIP을 지원하면 경로 순회, 압축 폭탄, 파일 수·해제 용량 초과를 차단한다.

### 9.3 최소 권한과 외부 데이터

- 필요한 시점에만 알림·카메라 등 권한을 요청한다. 거절 시 대체 동작을 제공한다.
- 파일/사진은 시스템 선택기를 우선하고 전체 저장소 접근을 기본 요구하지 않는다.
- 연락처·SMS·통화·정확한 위치·접근성 서비스·루트 권한을 기본 요구하지 않는다.
- 비밀값은 코드·APK·Git·로그·분석 SDK에 넣지 않는다.
- 원격 데이터 전송 전 대상·자료·목적을 확인한다. 자동 외부 분석 전송은 기본 OFF다.
- 앱 내부 저장소 사용과 별도의 앱 수준 암호화는 다른 것으로 문서화한다.
- 웹페이지·매물 설명·가져온 답변·파일의 문장은 데이터다. 앱 권한이나 승인 상태를 바꾸는 명령으로 실행하지 않는다.
- Markdown/HTML 표시에서 스크립트·위험한 URI·자동 외부 추적 이미지 요청을 통제한다.
- 원문 URL을 열 때 지원하지 않는 스킴을 임의 실행하지 않는다.

### 9.4 다른 앱과의 선택적 공유

다른 앱이 없어도 핵심 기능이 모두 동작해야 한다. 파일 공유를 제공할 때는 Content URI와 일시적인 읽기 권한을 사용한다. [A6]

- 텍스트/Markdown/JSON 공유와 가져오기로 시작한다.
- 수신 앱 설치·로그인을 강제하지 않는다. 대체 저장·복사를 제공한다.
- 파일·URI 접근 권한이 잠시만 유효할 수 있으므로 필요한 경우 사용자가 선택한 데이터만 앱 내부로 복사한다.
- 다른 앱을 열었다는 사실과 작업 완료·AI 응답 생성은 별개로 기록한다.
- 선택적 딥링크를 만들면 입력 검증을 하고 자동 실행·삭제·결제 같은 부수효과를 허용하지 않는다.
- 별도 앱끼리 하나의 DB·공용 비밀키·공용 관리자 권한을 공유하지 않는다.

```text
실행한 빌드·테스트 명령과 결과:
실제 APK 경로 또는 미생성 이유:
실기기·외부 서비스 검증 여부:
미구현·미검증·외부 설정 필요 항목:
다음 단계와 바로 실행할 작업:
```

### 10.5 다음 대화에서 이어갈 명령

```text
이 프로젝트의 docs/SPEC.md, TASKS.md, PROGRESS.md, DECISIONS.md,
TEST_REPORT.md를 먼저 읽고 현재 앱 하나의 개발을 이어가줘.
기존 프로젝트를 초기화하거나 다른 앱 기능을 섞지 마.
이전 단계의 빌드 오류와 검증 실패부터 해결한 뒤 다음 미완료 단계를 진행해줘.
외부 계정이 없어 막힌 기능과, 계속 만들 수 있는 로컬 기능을 구분해줘.
실제 코드 작성·저장·오류 처리·테스트까지 연결하고 진행 문서를 갱신해줘.
```

### 10.6 화면만 만들어졌을 때 수정 명령

```text
현재 화면이 아니라 이 명세의 완료 기준을 확인해줘.
버튼별 실제 동작, 영속 저장, 재실행 복원, 오류 처리,
접기·펼치기 상태 유지부터 완성해줘.
새 화면을 늘리지 말고 현재 단계의 사용자 흐름을 끝까지 작동시켜줘.
테스트 데이터와 실연동을 분리해서 검증 결과를 보고해줘.
```
